# v1.2 更新说明：铜钱真实化 + 摇一摇修复

## 本次改动
1. **铜钱逐枚分正反**：随机层改为逐枚掷正反（throwCoinsDetailed），三枚背面数决定爻象；
   每枚铜钱 3D 翻转后停在它真实掷出的那一面，爻象提示同步显示背数（如「2背 · 少阴」）。
   概率分布与公平性条款不变：10万次卡方=2.47 通过，各枚背面率≈50%，手势参数仍不进入随机函数。
2. **铜钱质感重做**：SVG 绘制青铜"乾隆通宝"——字面四字、背面满文纹、方孔、立缘、包浆、高光，
   双面各自建模，配合 3D 翻转动效。
3. **摇一摇缺陷修复（P1）**：原判定要求加速度持续超阈 800ms，但实际摇动在每次换向瞬间加速度
   会自然回落，旧逻辑被反复重置导致几乎无法触发。改为峰值计数法：1 秒内检测到 ≥3 次甩动峰值
   即掷爻，2.5 秒冷却防连发。无头模拟"峰-谷交替"序列验证：可触发、且冷却期内不重复。

## 关于「摄像头隔空手势」的评估（甲方问询第3条）
技术可行（浏览器内手部识别，如 MediaPipe Hands），但代价：需摄像头权限（用户敏感度远高于
运动传感器）、识别模型数 MB 起（破坏单文件离线架构）、中低端手机帧率与发热、误触发率高。
结论：不建议进 MVP；若摇一摇修复后体验仍不满足，可立项 V2 实验性功能（独立开关、按需加载模型）。
