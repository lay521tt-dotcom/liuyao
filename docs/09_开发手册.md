# 开发手册

> 适用对象：后续维护者（人类或 AI）。改动任何东西前，先读 README 的「核心口径」与 docs/03 开发文档。

## 1. 环境准备

```bash
node -v        # 需要 Node 18+
npm i -D esbuild jsdom        # 构建与无头测试
pip install opencc-python-reimplemented sxtwl lunar_python   # 仅数据工程需要
# PostgreSQL 15+：仅在改动内容/卦理数据时需要
```

## 2. 日常构建（改了引擎或界面后）

```bash
# 1) 构建引擎（两种产物：测试用 esm / 注入页面用 iife）
npx esbuild packages/hexagram-core/src/index.ts --bundle --format=esm  --outfile=packages/hexagram-core/dist/index.mjs
npx esbuild packages/hexagram-core/src/index.ts --bundle --format=iife --global-name=LiuYao --minify --outfile=/tmp/engine.iife.js

# 2) 注入引擎与数据快照，生成成品 index.html
python3 - << 'EOF'
html=open('apps/web/app_source.html').read()
eng=open('/tmp/engine.iife.js').read()
snap=open('data/data-snapshot.json').read()
open('index.html','w').write(html.replace('__ENGINE__',eng).replace('__SNAPSHOT__',snap))
EOF

# 3) 回归（必须 78/78，否则禁止提交）
node tests/run_golden.mjs
```

## 3. 改内容（卦辞/注解/现代解读）

内容唯一源头是 PostgreSQL，流程：建库 → 跑 `data/seed/` 下全部 SQL（schema → seed_core → seed_text_full → seed_modern → seed_solar_term → t6_fix）→ 修改对应种子 SQL → 重新入库 → `python3 data/export_snapshot.py` 重导快照 → 按第 2 节重建。
**禁止**直接编辑 data-snapshot.json 或 index.html 里的内联 JSON。

## 4. 改卦理规则（高危区）

卦宫/世应/纳甲由 `data/generate.py` 按定式规则推演生成，内置权威断言。任何改动：改脚本 → 跑通全部断言 → 重新生成 seed_core.sql → 入库 → 导快照 → 重建 → 黄金用例 78/78。同时必须在 `tests/golden_gen.py`（测试方独立实现）做对应修改并重新交叉比对——两套实现是互相制衡的，只改一边等于自废武功。

## 5. 测试体系

- `tests/run_golden.mjs`：78 条黄金用例全字段比对（CI 门禁）
- 随机分布检验：10 万次卡方（见 docs/04 测试说明书 T3，提交涉及 random 的改动时必跑）
- 真机清单：iOS 摇一摇授权、降级路径、375px 渲染（docs/04 T4/T5）
- 比对类脚本铁律：**先断言样本量，再断言一致性**（防空数据假阳性）

## 6. 发布

`index.html` 即整站。Commit → Push 后 GitHub Pages 自动发布（1–2 分钟）。回滚 = 在 GitHub Desktop History 里 revert 对应提交再 Push。

## 7. 版本路线与扩展点

V2 规则引擎：在 PaiPanResult 之上加 analyze() 纯函数层；V3 账号云同步：本地记录已带 uuid/synced 字段；V4 AI 解读：以排盘 jsonb 快照为输入独立成服务。详见 docs/03 第 9 节。

## 8. 红线清单

1. 卦理数据不许在代码里硬编码（评审第一检查项）
2. 手势力度/时长不许影响爻象概率
3. 不得引入任何在版权书籍的文字（内容查重脚本见 docs/06）
4. 注解与现代解读不得出现指向用户的吉凶断语
5. 黄金用例不全绿不提交，发现文档与实现冲突回上游改文档
