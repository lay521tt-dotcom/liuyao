## 1. 项目概述

### 1.1 一句话定位
一个移动端优先（H5）的六爻排盘工具网站：用户在线起卦，系统自动完成专业排盘，并展示《周易》卦辞爻辞原文与注解。

### 1.2 MVP 边界（甲方已拍板）
- 解卦深度：**只排盘 + 原文注解**，不做规则引擎提示，不做 AI 智能解卦
- 商业模式：本期不做任何付费功能，不接支付
- 平台：H5 手机网页为主，桌面端可用即可（响应式降级）

### 1.3 设计原则
1. 排盘结果必须 100% 符合传统纳甲筮法规则，宁可少做功能，不可排错一爻
2. 移动端单手可完成完整占卜流程
3. 占卜过程有仪式感（摇卦动效），但不阻塞快速使用（提供手动录入捷径）

## 2. 目标用户与核心场景

| 用户画像 | 场景 | 核心诉求 |
|---|---|---|
| 易学爱好者/自学者 | 自己摇了铜钱，想快速排盘验证 | 手动录入爻象，秒出专业卦盘 |
| 好奇的普通用户 | 遇事想占一卦图个参考 | 流程简单，看得懂结果 |
| 易学从业者 | 给人排盘时需要一个趁手工具 | 排盘信息完整准确（纳甲/世应/六亲/六神/旬空） |

## 3. 功能范围

### 3.1 本期做（P0 = 必须，P1 = 尽量）

**F1 起卦模块（P0）**
- F1.1 模拟摇卦：以手势为主要交互模拟掷三枚铜钱（摇晃手机/长按蓄力后甩动），共六次逐爻生成；必须提供点击摇卦作为降级方案（随机数生成方式见 6.2，手势交互细节见《页面交互说明书》）
- F1.2 手动录入：用户已有线下摇卦结果，按爻逐次录入「老阴/少阳/少阴/老阳」（即三枚铜钱的背面数 0~3）
- F1.3 时间起卦（梅花式取卦转六爻盘）（P1，可砍）
- F1.4 占问信息：起卦前可填写「所占何事」（选填，分类标签：事业/感情/财运/健康/出行/其他 + 自由文本）

**F2 排盘模块（P0）—— 本项目核心，规则详见第 5 章**
- 本卦、变卦（有动爻时）的卦名、卦象、上下卦宫
- 每爻：阴阳爻象、动爻标记、纳甲（天干地支五行）、六亲、世应、六神
- 卦宫归属、旬空、月破、日辰月建展示（按起卦时间自动取干支历）

**F3 内容展示模块（P0）**
- 本卦与变卦的卦辞原文、动爻对应爻辞原文（含用九/用六）
- 每条原文配白话注解（注解内容必须原创撰写或公有领域古注，禁止抄录在版权图书，见 6.4）
- 《象传》《彖传》相关原文（P1）

**F4 记录模块（P1）**
- 本地保存占卜历史（浏览器本地存储，本期不做账号体系）
- 单卦结果生成分享图/分享链接（P1，可砍）

**F5 基础页面（P0）**
- 首页（起卦入口）、排盘结果页、历史记录页、关于/免责声明页

### 3.2 本期明确不做（防止范围蔓延）
- 用户注册登录、账号体系
- 任何形式的付费、会员、打赏
- AI 解卦、吉凶结论输出、用神自动判断
- 人工大师解卦、社区、评论
- App 原生客户端、小程序

### 3.3 后续版本路线（仅作架构预留参考）
- V2：规则引擎结构化提示（用神、旺衰、动变关系提示）
- V3：账号体系 + 云端历史
- V4：AI 个性化解读（需另立合规与话术规范）

## 4. 核心用户流程

```
首页 → 选择起卦方式 → （选填占问事项）
    → 摇卦/录入六爻（自下而上：初爻→上爻）
    → 排盘结果页（卦盘 + 原文注解，可折叠分区）
    → 保存到历史 / 重新起卦
```

关键交互要求（给 UX 的硬约束）：
- 摇卦必须逐爻进行共六次，顺序自下而上，界面需明确当前摇到第几爻
- 排盘结果页信息密度高，移动端需分区呈现：卦盘区（固定专业表格样式）+ 原文注解区（可展开）
- 任何结果页面底部固定展示免责声明入口

## 5. 业务规则规范（排盘算法的业务依据）

以下规则为传统京房纳甲筮法定式，开发与测试以此为准，不允许"差不多"。

### 5.1 爻象生成
三枚铜钱一掷，按背面（字/背约定需在 UI 中图示说明）数量定爻：
- 3 背 = 老阳（动爻，阳变阴）
- 2 背 = 少阴（静爻）
- 1 背 = 少阳（静爻）
- 0 背 = 老阴（动爻，阴变阳）

六次成卦，自下而上为初、二、三、四、五、上爻。老阳/老阴为动爻，动则成变卦。

### 5.2 卦宫与世应
六十四卦分属八宫（乾、坎、艮、震、巽、离、坤、兑），每宫八卦：本宫卦、一世至五世、游魂、归魂。世爻位置随宫序定式：本宫卦世在上爻，一世至五世卦世在初至五爻，游魂世在四爻，归魂世在三爻。应爻与世爻相隔两位。系统内置 64 卦 → 卦宫/世应 对照表，不做运行时推导。

### 5.3 纳甲（装干支）
按八卦纳甲定式为内外卦各爻配天干地支与五行（如乾内卦甲子、甲寅、甲辰，外卦壬午、壬申、壬戌等八宫全表）。开发文档需附完整 64 卦纳甲表作为静态数据，禁止程序员凭记忆编写。

### 5.4 六亲
以卦宫五行为「我」，各爻地支五行与之比较：生我者父母、我生者子孙、克我者官鬼、我克者妻财、比和者兄弟。

### 5.5 六神
按起卦日天干起六神排初爻至上爻：甲乙起青龙、丙丁起朱雀、戊起勾陈、己起腾蛇、庚辛起白虎、壬癸起玄武，依「青龙→朱雀→勾陈→腾蛇→白虎→玄武」循环上排。

### 5.6 历法与旬空月破
- 起卦时间换算为干支历（年月日时四柱），换算需采用真太阳时或至少标准北京时间 + 节气分界月柱，日柱换日口径【甲方已定稿】：23 点换日（晚子时归次日），UI 需注明此口径
- 旬空：按日柱所在旬定两个空亡地支
- 月破：与月建地支相冲者为月破

### 5.7 内容库
- 64 卦卦辞 + 386 条爻辞（384 爻 + 用九用六），原文采用通行本《周易》（公有领域）
- 白话注解：原创撰写，卦辞注解 60–150 字、爻辞注解 20–150 字（移动端逐爻阅读以简明为佳，V1.1修订），语气客观平实，不给吉凶断语（写「此爻象征…古人认为…」而非「你将会…」）
- 现代解读（V1.1新增）：每卦一条原创现代白话解读（60–200字），讲处境与方法、不作吉凶预言，呈现于古注之后、默认折叠

## 6. 非功能需求

### 6.1 性能与兼容
- H5 移动优先，最低兼容 iOS Safari / Android Chrome 近三年版本
- 排盘为纯前端可计算逻辑亦可后端计算，由架构师决策，但首屏加载 < 2s，排盘出结果 < 500ms

### 6.2 随机性
模拟摇卦使用密码学安全随机数（如 crypto.getRandomValues），保证四种爻象概率符合三枚铜钱的真实分布（1/8、3/8、3/8、1/8），禁止用普通伪随机做简单取模导致分布偏差。

### 6.3 合规与免责
- 全站显著位置提供免责声明：内容仅供传统文化研究与娱乐参考，不构成医疗、投资、法律等任何决策建议
- 不收集个人敏感信息；占问内容仅存本地
- 未成年人提示（P1）

### 6.4 版权红线
- 可用：《周易》经传原文、纳甲筮法传统规则（公有领域）
- 禁用：任何在版权现代著作（含《周易说什么》等）的成段文字。此类书籍仅作团队理解业务的内部参考

## 7. 验收标准（给测试工程师的硬指标）

1. **卦理黄金用例集**：建立不少于 70 个已知正确答案的卦例（覆盖八宫各宫、含动爻/无动爻/六爻全动、游魂归魂卦、跨旬跨节气日期），系统排盘输出与基准逐字段比对，通过率必须 100%
2. 四种爻象的随机分布在 10 万次模拟中与理论值偏差 < 1%
3. 全部 64 卦 + 386 条爻辞内容完整无缺漏、无错字（抽检 + 全量 diff 校对）
4. 移动端核心流程（起卦→排盘→查看注解）在 375px 宽度下无横向滚动、无遮挡
